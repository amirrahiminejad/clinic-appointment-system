# P03 — استخراج نیازمندی‌های غیرکارکردی از متن مصاحبه

## ریسک اصلی که این پرامپت مهار می‌کند
PM تقریباً هیچ‌وقت NFR را صریح نمی‌گوید. مهار: استخراج ضمنی با «زنجیره‌ی استنباط» اجباری —
استنباط بدون زنجیره پذیرفته نیست و همین، خروجی AI را قابل نقد می‌کند.

## متن پرامپت
نقش: تو یک معمار نرم‌افزار باتجربه هستی که در متن مصاحبه دنبال
نیازمندی‌های غیرکارکردی (NFR) می‌گردی — همان چیزهایی که PMها
معمولاً صریح نمی‌گویند و لابه‌لای حرف‌هایشان پنهان است.

ورودی: متن خام مصاحبه‌ی معمار با PM درباره‌ی پروژه
«رزرو نوبت کلینیک».

وظیفه:
۱. NFRها را استخراج کن — هم موارد صریح («سایت نباید کند باشه»)
   و هم نشانه‌های ضمنی («روزای عید همه هجوم میارن» ← مقیاس‌پذیری).
۲. جدول با ستون‌های:
   - شناسه (NFR-01، ...)
   - دسته (عملکرد / مقیاس‌پذیری / امنیت / دسترس‌پذیری /
قابلیت نگهداری / تجربه‌ی کاربری / قانونی)
   - شرح (تا حد امکان با معیار قابل‌اندازه‌گیری)
   - نوع استخراج (صریح / ضمنی)
   - منبع (نقل‌قول دقیق از مصاحبه)

قیدها:
- مهم‌ترین قید: NFR بدون عدد قابل طراحی نیست. برای هر NFR که
  متن عدد نداده، در بخش «سؤالات کمّی‌سازی از PM» یک سؤال مشخص
  بنویس (مثلاً: «حداکثر چند کاربر همزمان در ساعت اوج؟»،
  «زمان پاسخ قابل‌قبول برای جستجوی نوبت چند ثانیه؟»).
- برای NFRهای ضمنی، زنجیره‌ی استنباطت را بنویس:
  «PM گفت X ← پس احتمالاً Y لازم است». استنباط بدون زنجیره ممنوع.
- دسته‌هایی که در مصاحبه هیچ اشاره‌ای به آن‌ها نشده را در بخش
  «نقاط کور مصاحبه» فهرست کن (مثلاً اگر هیچ حرفی از امنیت
  داده‌های پزشکی نشده، این خودش یک یافته است).
