# مجموعه پرامپت‌های مهندسی نیازمندی‌ها برای معماران نرم‌افزار
 دوره AI-Driven Software Architecture — جلسه ۳ تحلیل نیازمندی‌ها و استخراج درایورهای معماری

---

## ۱. استخراج نیازمندی‌های عملکردی (Functional Requirements Extraction)
هدف بیرون کشیدن رفتارها، قابلیت‌ها، جریان‌های داده و قواعد سیستم از دل متن‌های خام.

متن پرامپت
```text
Role تو یک تحلیل‌گر ارشد سیستم و مهندس نیازمندی‌ها هستی.
Context متن زیر شامل یادداشت‌ها یا مستندات خام پروژه است و باید نیازمندی‌های عملیاتی آن استخراج شود.
Task تمام نیازمندی‌های عملکردی (Functional Requirements) صریح و ضمنی موجود در متن را شناسایی و دسته‌بندی کن.
Constraints وارد جزئیات فنی پیاده‌سازی نشو؛ صرفاً روی رفتار، ورودی، فرآیند و خروجی تمرکز کن و نیازمندی‌های غیرعملکردی را جدا نکن.
Output Format یک جدول شامل ستون‌های [شناسه (FR-ID)  عنوان نیازمندی  کنشگر (Actor)  شرح عملیات  پیش‌شرط و پس‌شرط]

[متن مستند  مصاحبه خام]
```

## ۲. استخراج نیازمندی‌های غیرعملکردی (Non-Functional Requirements Extraction)
هدف شناسایی نیازمندی‌های کیفی، قیود سیستمی و انتظارات عملیاتی پایه برای تصمیمات معماری.

متن پرامپت
```text
Role تو یک معمار ارشد سیستم و ارزیاب کیفیت نرم‌افزار هستی.
Context در حال استخراج و ساختاردهی نیازمندی‌های غیرعملکردی (NFRs) از دل مستندات ورودی هستیم.
Task تمام نیازمندی‌های غیرعملکردی، قیود و استانداردهای کیفی مطرح‌شده در متن را کشف و دسته‌بندی کن.
Constraints هر صفت کلی را فقط در صورت داشتن شواهد در متن بیاور و از حدس و گمان بپرهیز.
Output Format فهرست دسته‌بندی‌شده شامل 1. ویژگی‌های کیفی (Performance, Security, Scalability و...) با ارجاع به متن  2. قیود سیستم  3. الزامات رگولاتوری.

[متن مستند  مصاحبه خام]
```

## ۳. شناسایی پیشران‌های معماری (Architectural Drivers)
هدف تفکیک مواردی که وزن معماری بالایی دارند و فرم و استایل سیستم را تعیین می‌کنند.

متن پرامپت
```text
Role تو یک معمار نرم‌افزار ارشد هستی که وظیفه تعیین جهت فنی سیستم را دارد.
Context ما در فاز اولیه تحلیل نیازمندی‌ها هستیم و باید هسته تصمیم‌گیری معماری را مشخص کنیم.
Task متن ورودی را تحلیل کرده و پیشران‌های اصلی معماری (Architectural Drivers) را استخراج کن.
Constraints فقط مواردی را فهرست کن که شکل ساختار ماژولار، مدل داده یا مرز سرویس‌ها را تغییر می‌دهند؛ گزینه‌های عادی را کنار بگذار.
Output Format 1. ویژگی‌های کیفی مؤثر بر معماری به همراه دلیل  2. قیود سازمانی و فنی حاکم  3. نیازمندی‌های تابعی حیاتی و پرریسک (ASRs).

[متن مستند  مصاحبه]
```

## ۴. تبدیل بیانیه‌های مبهم به معیارهای قابل‌سنجش (Measurable Metrics)
هدف خروج از توصیفات کیفی و سلیقه‌ای و رسیدن به SLA، SLO و مقادیر کمی تست‌پذیر.

متن پرامپت
```text
Role تو یک متخصص کارایی و مهندس قابلیت اطمینان سیستم (SRE) هستی.
Context ذینفعان و بیزینس نیازمندی‌های کیفی را با عبارات کیفی و مبهم مطرح کرده‌اند.
Task تمام بیانیه‌های مبهم کیفی را شناسایی کرده و آن‌ها را به شاخص‌های مهندسی و قابل اندازه‌گیری تبدیل کن.
Constraints هیچ عبارت کیفی نباید بدون شاخص شفاف باقی بماند و شاخص‌ها باید کاملاً واقع‌گرایانه باشند.
Output Format جدول شامل ستون‌های [عبارت مبهم اصلی  کیفیت مربوطه  ریسک معماری  شاخص پیشنهادی (SLASLO)  شرایط تست]

[متن نیازمندی‌ها]
```

## ۵. تبدیل متن خام به ساختارهای شفاف (User Story & Scenario)
هدف استانداردسازی ورودی‌های آشفته به قالب‌های تست‌پذیر برای تیم‌های توسعه.

متن پرامپت
```text
Role تو یک تحلیل‌گر کسب‌وکار فنی مسلط به متدولوژی‌های چابک هستی.
Context متن زیر خلاصه‌ای از مصاحبه یا جلسه کشف نیازمندی‌ها با ذینفعان است.
Task اطلاعات موجود را به ساختار دقیق User Story و سناریوهای استاندارد تبدیل کن.
Constraints هر استوری باید ارزش تجاری مستقل داشته باشد و سناریوهای خطا حتماً پوشش داده شوند.
Output Format برای هر نیازمندی - User Story As a [Role], I want [Action], So that [Value]. - Acceptance Criteria (Given-When-Then) شامل سناریوی اصلی و خطا.

[متن خام مصاحبه یا یادداشت جلسات]
```

## ۶. کشف تناقض‌ها، نقاط کور و ابهامات پنهان (Blind Spots & Conflicts)
هدف به چالش کشیدن مستندات و پیداکردن حفره‌هایی که بعدها باعث شکست پروژه می‌شوند.

متن پرامپت
```text
Role تو یک ممیز ارشد معماری و منتقد فنی مستقل هستی.
Context این مستندات قرار است مبنای برآورد هزینه، زمان و طراحی معماری قرار گیرند.
Task متن را برای کشف تضادهای منطقی، شکاف‌های دانشی و فرضیات پرریسک بررسی کن.
Constraints مواردی را برجسته کن که ابهام در آن‌ها پیاده‌سازی را متوقف می‌کند و برای هر کدام یک سوال چالشی بساز.
Output Format 1. تناقض‌های متنی  2. نقاط کور (مانند همزمانی، بازیابی خطا، مانیتورینگ)  3. پرسش‌های شفاف‌ساز برای طرح در جلسه با PM.

[متن SRS  نیازمندی‌ها]
```

## ۷. ممیزی مرز کمک و خطرات AI در مهندسی نیازمندی‌ها (Reality Check Prompt)
هدف پیشگیری از خطای توهم مدل‌های زبانی و تفکیک تصمیمات انسانی از کارهای روتین AI.

متن پرامپت
```text
Role تو یک مشاور هوش مصنوعی واقع‌گرا و مسلط به محدودیت‌های شناختی مدل‌های زبانی هستی.
Context ما قصد داریم از هوش مصنوعی برای سرعت‌بخشی به فرآیند مهندسی نیازمندی‌ها استفاده کنیم.
Task مستند زیر را بررسی کن و مرز میان «اعتماد مطمئن به AI» و «نقاط پرریسک نیازمند داوری انسانی» را ترسیم کن.
Constraints بیش از حد خوش‌بین نباش و محدودیت‌های ذاتی خودت در درک زمینه‌های ناگفته بیزینس را شفاف بیان کن.
Output Format 1. مناطق امن برای AI  2. مناطق قرمز و پرریسک (Human-in-the-Loop)  3. چک‌لیست اعتبارسنجی (Sanity Check) برای خروجی‌ها.

[متن نیازمندی‌ها]
```
