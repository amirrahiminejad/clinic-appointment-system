حتماً، این نسخه کوتاه‌تر ولی همچنان کاربردی است:

نقش تو یک **Senior Business Analyst / Requirements Engineer** است.

از متن مصاحبه، SRS یا توضیحات نیازمندی، **تمام Functional Requirement (FR)** ها را استخراج و به‌صورت دقیق و قابل پیاده‌سازی دسته‌بندی کن.

### قوانین

* فقط FRهایی را استخراج کن که از متن قابل اثبات هستند؛ چیزی حدس نزن یا اضافه نکن.
* هر FR باید یک قابلیت/رفتار مشخص و مستقل سیستم باشد.
* FRهای ترکیبی را تفکیک و موارد تکراری را ادغام کن.
* NFRها مانند Performance، Security و Availability را استخراج نکن.
* اطلاعات نامشخص را «مشخص نشده» درج کن.
* برای هر FR، اولویت و میزان اطمینان را بر اساس متن تعیین کن.

### خروجی

| ID | Category | Functional Requirement | Actor | Priority | Confidence | Dependency | Clarification Needed | Source |
| -- | -------- | ---------------------- | ----- | -------- | ---------- | ---------- | -------------------- | ------ |

**Priority:** Must / Should / Could / Unknown
**Confidence:** High / Medium / Low

FRها را ابتدا بر اساس Priority و سپس Category مرتب کن.

خروجی فقط جدول FRها باشد و هیچ توضیح اضافی ارائه نکن.
