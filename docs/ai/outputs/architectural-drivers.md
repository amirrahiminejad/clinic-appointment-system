# Architectural Drivers & Quality Attributes

## ۱. هدف و محدوده (Purpose & Scope)

| مورد           | شرح                                                                                                   |
| -------------- | ----------------------------------------------------------------------------------------------------- |
| هدف            | شناسایی نیازمندی‌هایی که بر ساختار ماژول‌ها، مدل داده، یکپارچگی تراکنشی و مرز سرویس‌ها اثر می‌گذارند. |
| مرحله پروژه    | تحلیل اولیه نیازمندی‌ها                                                                               |
| محدوده         | هسته نوبت‌دهی، مدیریت پزشک و بیمار، برنامه کاری، امنیت و تاریخچه نوبت‌ها                              |
| مبنای تحلیل    | سند PRD سامانه نوبت‌دهی کلینیک                                                                        |

| خارج از محدوده | جزئیات پیاده‌سازی، انتخاب قطعی فناوری و تصمیم‌های استقرار تأییدنشده                                   |

| AD-06 | P1 — بالا                 | چرخه عمر نوبت                   | ثبت، تأیید، لغو و تکمیل نوبت باید وضعیت‌های روشن داشته باشند.                     | تعریف وضعیت‌ها و انتقال‌های مجاز در دامنه نوبت‌دهی            |

| AD-09 | P1 — بالا                 | کارایی و مقیاس‌پذیری            | جست‌وجو و عملیات رزرو باید در بار مورد انتظار پاسخ‌گو باشند.                      | شاخص‌گذاری، بهینه‌سازی پرس‌وجو و آزمون بار                    |

## ۳. ویژگی‌های کیفی مؤثر بر معماری (Quality Attributes)

| ویژگی کیفی                      | سناریوی مورد انتظار                                           | معیار ارزیابی                                                                       | اولویت |
| ------------------------------- | ------------------------------------------------------------- | ----------------------------------------------------------------------------------- | ------ |
| یکپارچگی (Integrity)            | چند کاربر هم‌زمان یک ظرفیت را رزرو می‌کنند.                   | هیچ رزرو ناسازگار یا بیش از ظرفیت ایجاد نشود.                                       | P0     |
| امنیت (Security)                | کاربر بدون مجوز درخواست مشاهده اطلاعات بیمار را ارسال می‌کند. | دسترسی رد شود و داده حساس افشا نشود.                                                | P0     |
| حسابرسی‌پذیری (Auditability)    | نوبت تغییر یا لغو می‌شود.                                     | سابقه تغییر قابل پیگیری باقی بماند.                                                 | P0     |
| سازگاری (Consistency)           | عملیات تغییر زمان با شکست مواجه می‌شود.                       | وضعیت و ظرفیت در حالت سازگار باقی بمانند.                                           | P0     |
| کارایی (Performance)            | کاربر زمان‌های قابل‌رزرو را جست‌وجو می‌کند.                   | هدف اولیه PRD: کمتر از ۲ ثانیه برای صدک ۹۵ درخواست‌های مشمول هدف، پس از اعتبارسنجی. | P1     |
| تاب‌آوری (Resilience)           | پاسخ عملیات به دلیل timeout دریافت نمی‌شود.                   | نتیجه قابل پیگیری باشد و تکرار درخواست رزرو ناخواسته ایجاد نکند.                    | P1     |
| نگهداشت‌پذیری (Maintainability) | تغییر در برنامه کاری پزشک انجام می‌شود.                       | تغییر بدون اصلاح غیرضروری سایر ماژول‌ها قابل اعمال باشد.                            | P1     |
| توسعه‌پذیری (Extensibility)     | خدمت جدید با مدت متفاوت اضافه می‌شود.                         | نیاز به بازطراحی گسترده هسته رزرو نباشد.                                            | P2     |
| مقیاس‌پذیری (Scalability)       | بار درخواست‌ها افزایش پیدا می‌کند.                            | اهداف پاسخ‌گویی و صحت رزرو در بار هدف حفظ شوند.                                     | P1     |

توجه: معیار عددی کارایی از هدف اولیه PRD گرفته شده است؛ سایر معیارها باید در آزمون‌های پذیرش و آزمون‌های غیرعملکردی به شاخص‌های اندازه‌پذیر تبدیل شوند.

## ۴. نیازمندی‌های حیاتی معماری (Architecturally Significant Requirements — ASRs)

| شناسه  | نیازمندی حیاتی                     | ریسک در صورت عدم تحقق                         | روش اعتبارسنجی                                |
| ------ | ---------------------------------- | --------------------------------------------- | --------------------------------------------- |
| ASR-01 | جلوگیری از رزرو هم‌زمان ناسازگار   | ثبت نوبت متداخل یا بیش از ظرفیت               | آزمون رقابت هم‌زمان و بررسی قیود پایگاه داده  |
| ASR-02 | تغییر و لغو سازگار نوبت            | ازدست‌رفتن نوبت یا ناسازگاری ظرفیت            | آزمون تراکنش، شکست عملیات و بازیابی وضعیت     |
| ASR-03 | اعمال مجوز دسترسی به اطلاعات بیمار | افشای اطلاعات یا تغییر غیرمجاز                | آزمون دسترسی نقش‌محور و آزمون منفی امنیتی     |
| ASR-04 | حفظ سابقه تغییرات مهم              | از بین رفتن قابلیت ردیابی                     | آزمون تغییر، لغو و بررسی سوابق ثبت‌شده        |
| ASR-05 | کنترل نتیجه نامشخص عملیات          | رزرو تکراری یا تأیید کاذب                     | آزمون timeout، ارسال مجدد و پیگیری نتیجه      |
| ASR-06 | محاسبه صحیح زمان قابل‌رزرو         | رزرو خارج از ساعات کاری یا در زمان عدم دسترسی | آزمون قواعد برنامه کاری، مدت نوبت و هم‌پوشانی |
| ASR-07 | اجرای سیاست نگهداری داده           | نگهداری غیرمجاز یا حذف زودهنگام سابقه         | آزمون سیاست نگهداری، حذف و بازیابی پشتیبان    |

| CON-02 | ورود مستقیم بیمار و رزرو سلف‌سرویس هنوز نیازمند تعیین تکلیف است.      | پرسش باز                                               | اثر بر احراز هویت، مجوزها و گردش کار رزرو              |
| CON-03 | حجم کاربران و درخواست‌های هم‌زمان مشخص نیست.                          | نامشخص                                                 | جلوگیری از انتخاب زودهنگام معماری توزیع‌شده            |
| CON-04 | سیاست نگهداری داده و الزامات قانونی باید مشخص شوند.                   | نیازمند تأیید                                          | اثر بر تاریخچه، حذف و آرشیو                            |
| CON-05 | مدت نوبت و وابستگی آن به نوع خدمت مشخص نیست.                          | پرسش باز                                               | اثر بر مدل داده و محاسبه ظرفیت                         |
| CON-06 | سیاست تأیید دستی یا خودکار نوبت باید تأیید شود.                       | پرسش باز                                               | اثر بر وضعیت‌های نوبت و تخصیص ظرفیت                    |
| CON-07 | فناوری پایگاه داده و زیرساخت استقرار هنوز در این تحلیل قطعی نشده‌اند. | تصمیم فنی باز                                          | تعیین سازوکار نهایی تراکنش و کنترل هم‌پوشانی           |
| CON-08 | معماری ریزسرویس الزام تأییدشده‌ای نیست.                               | پیشنهاد معماری: شروع با یکپارچه‌ساز ماژولار            | کاهش پیچیدگی اولیه و حفظ امکان استخراج تدریجی سرویس‌ها |

| مرز ماژول‌ها | تفکیک منطقی نوبت‌دهی، برنامه پزشک، بیمار، دسترسی و تاریخچه | کاهش وابستگی و مشخص‌کردن مالکیت قواعد دامنه      |
| مدل داده     | تعریف صریح نوبت، بازه زمانی، برنامه کاری و سابقه تغییرات   | پشتیبانی از سازگاری و حسابرسی                    |
| تراکنش‌ها    | متمرکزکردن ثبت و تغییر نوبت در یک مرز تراکنشی              | جلوگیری از رزرو ناسازگار                         |
| امنیت        | اعمال مجوز در مرز عملیات کاربردی و دسترسی به داده          | جلوگیری از دسترسی غیرمجاز                        |

| تکامل آینده  | حفظ قراردادهای روشن میان ماژول‌ها                          | امکان استخراج تدریجی سرویس‌ها در صورت اثبات نیاز |

## ۸. معیار تکمیل تحلیل معماری

| معیار           | وضعیت مورد انتظار پیش از تثبیت طراحی تفصیلی                   |
| --------------- | ------------------------------------------------------------- |
| پیشران‌های P0   | قواعد و معیارهای پذیرش مشخص شده باشند.                        |
| مدل زمان‌بندی   | رابطه پزشک، خدمت، مدت نوبت و ظرفیت تعیین تکلیف شده باشد.      |
| چرخه عمر نوبت   | وضعیت‌ها و انتقال‌های مجاز تأیید شده باشند.                   |
| امنیت و نگهداری | نقش‌ها، الزامات حفاظت از داده و سیاست نگهداری مشخص شده باشند. |
| اهداف کیفی      | بار هدف، معیار پاسخ‌گویی و اهداف بازیابی توافق شده باشند.     |
| ASRها           | سناریوهای آزمون و روش اعتبارسنجی تعریف شده باشند.             |
| فرضیات معماری   | فرضیات از قیود قطعی جدا و برای بازنگری مستند شده باشند.       |

جمع‌بندی: این مستند باید مرجع مشترک تحلیل نیازمندی‌ها و طراحی معماری باشد. پیشران‌های P0 مبنای طراحی هسته سیستم هستند؛ P1ها باید پیش از تثبیت طراحی تفصیلی تعیین تکلیف شوند؛ و P2ها باید بدون تحمیل پیچیدگی غیرضروری، در مرزبندی ماژول‌ها قابل پشتیبانی باشند.
